# Troubleshooting Core

Start with the first symptom that matches the project.

## Core types are not visible

Core assemblies have `autoReferenced` disabled. Add explicit references from the consuming asmdef:

- `BovineLabs.Core` for runtime APIs.
- `BovineLabs.Core.Authoring` for bakers and settings authoring.
- `BovineLabs.Core.Editor` for editor windows, inspectors, and asset tools.
- `BovineLabs.Testing` for shared test fixtures.

Keep editor-only references out of player assemblies. See [Getting started](getting-started.md#add-assembly-references).

## An optional integration is missing

APIs for NetCode, Physics, Localization, Splines, Terrain, and VFX Graph are conditionally compiled. Verify that the matching package or Unity module is installed and that Unity enabled the expected version-define symbol.

An asmdef reference listed by Core does not install the package that provides it.

## A generated facet or `AsMap` method is missing

Confirm that the consuming asmdef references `BovineLabs.Core` and that the Console has no earlier compiler errors.

- Facets must be top-level `partial struct` types implementing `IFacet`.
- Generated byte-backed maps implement the matching `IDynamic*` interface.
- Entry-backed buffers implement `IDynamicDictionaryEntry`, `IDynamicMultiDictionaryEntry`, or `IDynamicHashSetEntry`.
- Nested dynamic-buffer marker types are not supported by the generator.

Entry-backed collections can still use the explicit `AsDynamicDictionary`, `AsDynamicMultiDictionary`, or `AsDynamicHashSet` extension while diagnosing generation. See [Dynamic buffer collections](DynamicCollections.md).

## A settings asset is missing or duplicated

Open **BovineLabs > Settings**. `EditorSettingsUtility.GetSettings<T>()` creates a missing asset; `TryGetSettings<T>()` does not.

Only one asset of each settings type is valid. Duplicate assets make selection or singleton initialization nondeterministic; remove the unintended copy rather than relying on discovery order.

For `SettingsBase` baking, also verify:

1. The target SubScene contains the expected `SettingsAuthoring` prefab or component.
2. **BovineLabs > Settings > Core > Editor Settings** maps the requested world key.
3. The baker calls `DependsOn` when it reads a settings asset directly.
4. The baked component exists exactly once before using `SystemAPI.GetSingleton<T>()`.

See [Settings](Settings.md).

## A ConfigVar is missing, grouped incorrectly, or will not edit

- Put `[Configurable]` on the owning class or struct.
- Use a static `SharedStatic<T>` field with `[ConfigVar]` and a unique context key.
- Use a globally unique lowercase name. The first segment before `.` is the ConfigVars window group.
- `isHidden: true` removes only the editor row; command-line and code access remain active.
- `isReadOnly: true` disables the editor field only while Play mode is active.
- Editor values live in local `EditorPrefs`, not project assets or version control.

Use **Reset To Default** from the field context menu or the window toolbar when a persisted value is invalid. See [ConfigVars](ConfigVars.md) for supported types and current complex-value limitations.

## `IEntityCommands` affects the wrong entity

`IEntityCommands.Entity` is mutable local state. `CreateEntity()` and `Instantiate(...)` replace it. Use overloads that take an explicit `Entity` when a builder touches more than one entity.

`BakerCommands` intentionally cannot instantiate, set names, or append to buffers. Fill the `DynamicBuffer<T>` returned by `AddBuffer` or `SetBuffer` during baking. See [Entity commands](EntityCommands.md).

## A dynamic collection reports an invalid capacity or corrupt lookup

Entry-backed dictionaries and sets require a power-of-two table length. Start from an empty buffer and call `EnsureCapacity`, or let the first insertion grow it.

Do not enumerate the raw buffer as logical entries: it contains empty slots and tombstones. Use the collection wrapper. After an external process remaps keys, call `ReconstructAfterRemap()` before lookup.

Generated byte-backed maps must be initialized before use. Keep their `Initialize()` call in baking or setup code. See [Dynamic buffer collections](DynamicCollections.md) and [Generated dynamic hash maps](DynamicHashMap.md).

## A native container throws a safety or disposal error

- Chain every writer and reader through the owning system dependency.
- Dispose allocator-owned containers only after their final job.
- Do not dispose a map backed by `DynamicBuffer<T>`; the entity owns it.
- Do not retain references returned by `GetOrAddRefUnsafe` across later writes that may resize or rehash.
- Return `PooledNativeList<T>` on the same thread that acquired it.

See [Collections](Collections.md) and [PooledNativeList](PooledNativeList.md).

## `BLLogger` is not available

`BLDebugSystem` creates the world-specific `BLLogger` singleton in the default, thin-client, and editor worlds selected by its world filter. A custom world that does not include that system will not have the singleton.

Use `BLGlobalLogger` when no world context exists. If a custom world needs `BLLogger`, include the normal Core debug system during world construction. See [Debugging and logging](Debug.md).

## A Core test leaks state or fails after another test

Derive from `ECSTestsFixture`, use its `Manager` rather than a stale external `EntityManager`, and call the base methods when overriding `Setup` or `TearDown`. Complete or assign all scheduled job handles before teardown.

Apply `[TestLeakDetection]` to individual test methods, not test classes. See [Testing](Testing.md).

## A Graph Toolkit drawer has the wrong layout

`GraphToolkitElementProperty` uses a foldout by default. Override `UseFoldout => false` for an inline value row. Use `SkipSingleRoot => true` only when a wrapper should expose its one composite child.

Keep callback state in `Cache<T>()` so multiple visible list elements do not share the same `SerializedProperty`. See [Inspectors](Inspectors.md).
